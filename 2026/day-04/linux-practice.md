# 1. Process checks:

## Commands:

- `ps aux` - It gives detailed information like CPU usage and memory usage, etc. of the processes running in the system.
- `ps -u username` - It filters only the specific user's processes.
- `ps -p PID` - It shows details for a specific process ID.
- `ps -ef` - It gives full-format listings of the running processes including parent process ID (PPID).
- `pgrep name` - It returns PID of the specified name.
- `pidof name` - It finds PID of the specific running executable.
- `ps -ef | grep name` - It find the process by searching its name from the full lists.
- `top` - It displays real-time information about running processes, CPU usage, memory/RAM usage, system in Linux.
- `htop` - It is an improved version of the top command, providing a colorful, user-friendly interface.

# 2. Service checks:

In modern systems, systemctl is the primary command to check and manage services. For older systems like SysVinit, service command is used.

## Commands:

- `systemctl status service_name` — It is used to check the detailed status of a specific service.
- `service service_name status` — It is used to check the status of a service using the older service command.
- `systemctl is-enabled service_name` — It is used to check whether a service is configured to start automatically on boot.
- `systemctl is-failed service_name` — It is used to check whether a service is in a failed state.
- `systemctl list-units --type=service --state=active` — It is used to list all currently active services.
- `systemctl is-active service_name` — It is used to check whether a specific service is currently running.
- `systemctl list-unit-files --type=service` — It is used to list all installed/available service unit files.
- `service --status-all` — It is used to list the status of all services using the older command.

# 3. Log checks:

journalctl command is used to view and manage logs from systemd journal.When a service is not working, journalctl helps you find the exact error and fix it fast.

## Commands-

- `journalctl -u service_name` - Shows logs for specific systemd service.
- `journalctl -f` - Follows live logs like (tail -f).
- `journalctl -p err` - Shows only error logs.
- `tail -f /var/log/syslog` - It continuously monitors the main system for new log entries.

## Mini troubleshooting steps

- **Step 1:** `ps aux` - to check the real-time CPU and memory usage.
- **Step 2:** `ps -u username` - display the processes running under a particular user account.
- **Step 3:** `systemctl list-unit-files --type=service` - Used to list the service unit files available on the system and their startup status.
- **Step 4:** `journalctl -u ssh` - To view logs generated by the ssh service for troubleshooting.
- **Step 5:** `kill -9 365` - forcefully terminate a process.
